# TUI Welcome Header 宽屏设计方案

本文档记录下一版 go-claude TUI welcome header 的设计稿。目标是参考原版 Claude Code 的品牌感和克制信息密度，但保留 go-claude 自己的品牌识别、中文可读性和权限安全提示。

## 设计目标

- 精致、简洁、大方，有呼吸感。
- 宽屏优先，减少高度占用，避免像后台参数面板。
- 品牌优先，运行信息其次，权限信息常驻，危险权限单独突出。
- 信息要用户友好，不直接堆字段；需要中文解释。
- 使用 go-claude 自己的像素风 mascot 替代简单 `GC` 方框。
- 保留窄屏降级，避免小终端挤压、折行和错位。

## 当前问题

上一版卡片的问题：

- 左侧像字段罗列，没有真正的品牌区。
- `Go / Claude` 两行文字不像 logo，缺少识别度。
- `GC` 方框只能算占位，不具备产品记忆点。
- model、provider、cwd 缺少中文语义，用户需要猜。
- Runtime/Session 权重过高，像运维面板，不像 welcome header。
- 信息纵向堆叠偏高，不适合宽屏。

## 宽屏推荐稿

默认宽屏高度控制在 9 行主体内容 + 边框/权限条，总体约 13 行。左侧是品牌 mascot 和弱状态，右侧是启动引导和会话状态。权限信息不进入普通状态区，统一在 panel 底部全宽权限条出现。

```text
╭─ Go Claude dev ───────────────────────────────────────────────────────────────────────────╮
│                                         │                                                  │
│                 ╭────────────╮          │ Quick start         Session                       │
│                 │  ●      ●  │          │ /init               ready · tools 31 · sandbox off │
│                 │     ▿      │          │   初始化项目说明    id 37ace34e-a50a-4170...      │
│                 │  ╭──────╮  │          │ /help                                            │
│                 │  │      │  │          │   查看命令                                       │
│                 ╰──╯      ╰──╯          │                                                  │
│       工作区 ~/GolandProjects/evaluation │                                                  │
│       模型 glm-5.1                       │                                                  │
├────────────────────────────────────────────────────────────────────────────────────────────┤
│  权限 ask  shift+tab 切换权限模式                                                        │
╰────────────────────────────────────────────────────────────────────────────────────────────╯
```

### 设计说明

- 标题回到边框左上角，主体区域保持原版 Claude Code 那种欢迎卡片气质。
- 超宽终端下 welcome panel 不再铺满全屏，宽度约为终端宽度的 70%，最小保持可读宽度，减少右侧大面积空白。
- 左侧不做 key-value 表格，保持“品牌 + 少量上下文”的弱信息结构。
- `GC` 方框替换为自有圆润像素助手 mascot，建立产品记忆点。
- mascot 采用暖橙/珊瑚色，危险权限使用更亮的橙红/红色，二者在语义上区分。
- mascot 必须有“脸”：眼睛 + 微表情，让欢迎页更有亲和力和记忆点。
- mascot 右侧使用竖线分隔成两个大区域：左侧品牌区，右侧信息区；分隔线跟随 panel 宽度左移，避免右侧空白过大。
- 左侧不再显示 `Welcome back!`，把视觉重心交给 mascot 和产品标题，减少空泛文案。
- `Quick start` 和 `Session` 在右侧内部组成双列信息块；命令和说明拆行显示，提高右侧信息密度，减少大面积空白。
- `Quick start` 下方必须始终显示 `/init`、`初始化项目说明`、`/help`、`查看命令`，不能依赖底部输入提示状态。
- `Session` 下方必须显示状态摘要和 session id，避免用户不知道当前会话身份。
- workspace 放左下第一行，带中文前缀：`工作区 ~/GolandProjects/evaluation`。
- 模型放左下第二行，和 workspace 左边界对齐，带中文前缀 `模型`，只显示模型名，不显示 provider / `custom/openai-compatible`。
- 状态摘要放右下：`ready · tools 31 · sandbox off`，不抢主信息。
- 权限条常驻在 panel 底部全宽显示；权限状态和 `shift+tab` 切换提示在左侧聚合展示，避免两端分散造成视觉距离过远。普通 `ask` 弱显示，危险 `allow` / `bypass` 在同一位置用克制暗色底条和 `>>` 强调。

## Mascot 方向

mascot 采用圆角终端助手方向：有完整外轮廓、清晰眼睛、克制表情和底部小脚，必须是 go-claude 自己的形象，不直接复制 Claude Code 原版。

### 视觉原则

- 小体量：控制在 7 行左右，不做复杂 ASCII 大图。
- 终端质感：使用 box drawing、圆角和少量符号，避免粗糙块状堆叠。
- 圆润感：外轮廓使用 `╭` / `╮` / `╰` / `╯`，整体更像产品标识。
- 脸部特征：两只眼睛必须清晰，嘴部只做轻表情，避免夸张。
- 暖色品牌：默认用橙色/珊瑚色，亲和但不刺眼。
- 可降级：不支持颜色或宽度不足时，可退回 `GC` 单字标识。
- 不喧宾夺主：mascot 是品牌记忆点，不承担状态展示。

### 推荐主形态

```text
        ╭────────────╮
        │  ●      ●  │
        │     ▿      │
        │  ╭──────╮  │
        │  │      │  │
        ╰──╯      ╰──╯
```

### 脸部特征

- 头部：顶部 `╭────────────╮`，形成干净的圆角轮廓。
- 脸部轮廓：头脸保持闭合圆角矩形，避免终端字体下的侧边悬线和左右错位。
- 眼睛：默认用 `● ●`，处理中用 `● ◌`，危险态用 `◆ ◆`，远看也能区分。
- 嘴部：默认 `▿` 轻微微笑；处理中 `·` 表示等待；危险态 `━` 表示严肃。
- 身体/底部：使用居中的小机身和等宽双脚，不能出现单侧悬空竖线，优先保证终端字体下的稳定对称。
- 表情必须轻：只通过眼睛和嘴部变化表达状态，不做大面积变形。
- 脸部必须稳：不同状态下外轮廓、宽度、高度和眼睛水平位置保持一致，避免 welcome header 抖动。

### 表情状态

默认欢迎态：

```text
        ╭────────────╮
        │  ●      ●  │
        │     ▿      │
        │  ╭──────╮  │
        │  │      │  │
        ╰──╯      ╰──╯
```

思考/处理中：

```text
        ╭────────────╮
        │  ●      ◌  │
        │     ·      │
        │  ╭──────╮  │
        │  │      │  │
        ╰──╯      ╰──╯
```

危险权限提醒态：

```text
        ╭────────────╮
        │  ◆      ◆  │
        │     ━      │
        │  ╭──────╮  │
        │  │      │  │
        ╰──╯      ╰──╯
```

### 动态策略

mascot 可以有简单动态，但默认保持克制，避免欢迎页显得廉价或干扰用户阅读。

- 默认欢迎态：静态，不循环动画。
- 思考/处理中：允许 2 帧轻动画，推荐 700-900ms 切换一次，只改变眼睛，不改变外轮廓。
- 危险权限态：不做循环动画。切换到 `allow` / `bypass` 时可以短暂高亮一次，随后保持静态严肃表情。
- 动画帧必须固定宽高，不能改变行数、列宽、边框、模型信息和 session 信息位置。
- 动画默认应可配置关闭，例如 `tui.mascot_animation = false`，方便低性能终端、录屏、截图验收和视觉回归测试。

处理中 2 帧建议：

```text
        ╭────────────╮
        │  ●      ◌  │
        │     ·      │
        │  ╭──────╮  │
        │  │      │  │
        ╰──╯      ╰──╯
```

```text
        ╭────────────╮
        │  ◌      ●  │
        │     ·      │
        │  ╭──────╮  │
        │  │      │  │
        ╰──╯      ╰──╯
```

### GC 标识规则

不要把 `GC` 硬塞进脸部。文字会破坏像素表情的质感，也会让脸部变拥挤。需要品牌缩写时，只在窄屏 fallback 或无 Unicode 支持时显示：

```text
[GC]
```

实现时优先保证在常见终端字体下不变形；如果宽度、高度或字体渲染不稳定，则退回无表情单字标识。

## 权限条与危险权限态

统一使用底部全宽权限条。正常 `ask` 也显示权限条，作为可发现的权限状态入口；`allow` / `bypass` / 高风险 sandbox 状态在同一位置做醒目提醒，避免普通状态区反复堆字段。

```text
╭─ Go Claude dev ───────────────────────────────────────────────────────────────────────────╮
│                                         │                                                  │
│                 ╭────────────╮          │ Quick start         Session                       │
│                 │  ◆      ◆  │          │ /init               ready · tools 31 · sandbox off │
│                 │     ━      │          │   初始化项目说明    id 37ace34e-a50a-4170...      │
│                 │  ╭──────╮  │          │ /help                                            │
│                 │  │      │  │          │   查看命令                                       │
│                 ╰──╯      ╰──╯          │                                                  │
│       工作区 ~/GolandProjects/evaluation │                                                  │
│       模型 glm-5.1                       │                                                  │
├────────────────────────────────────────────────────────────────────────────────────────────┤
│  >> 危险权限 bypass  shift+tab 切换权限模式                                               │
╰────────────────────────────────────────────────────────────────────────────────────────────╯
```

### 权限显示规则

- `ask`：底部权限条显示 `权限 ask  shift+tab 切换权限模式`，使用弱色。
- `allow`：底部权限条显示 `>> 危险权限 allow  shift+tab 切换权限模式`。
- `bypass`：底部权限条显示 `>> 危险权限 bypass  shift+tab 切换权限模式`。
- 宽屏模式下，权限条内容不要贴近左边框；权限文案的左起点必须比左侧上下文里的 `模型` 更靠右，建议至少右移 4-6 个终端 cell，约等于 10px+ 的视觉偏移，避免底部和上方信息形成“错位贴边”的廉价感。
- 用户按 `shift+tab` 切换权限后，底部权限条和底部 controls 必须同帧同步更新；非 alt-screen 终端下需要触发 renderer repaint，避免旧 welcome panel 残留。
- `sandbox off` 如果与 `allow/bypass` 同时出现，安全条文案优先表达权限风险，状态摘要继续保留 `sandbox off`。
- 权限条必须全宽独立成行，避免用户忽略权限模式。
- 视觉上危险权限条比普通权限条更醒目，但颜色要克制，推荐暗橙/琥珀色 bold，避免高饱和红色亮瞎眼。

## Mascot 备选方案池

当前圆角线框机器人方案用户反馈仍然“不对称、太丑、低质感”，因此后续 mascot 不应继续在该方案上小修小补。下面记录已经讨论过但尚未采纳的方向，方便后续比较和回溯。

### 方案 A：大字母品牌 Logo

用稠密 ASCII / block font 做 `GC` 或 `Go Claude`，类似终端工具常见启动大字标识。

```text
   ██████╗  ██████╗
  ██╔════╝ ██╔════╝
  ██║  ███╗██║
  ██║   ██║██║
  ╚██████╔╝╚██████╗
   ╚═════╝  ╚═════╝
```

- 优点：最稳、最产品化、不容易歪，也不会像廉价小图标。
- 缺点：没有脸，情绪状态只能靠颜色、状态 glyph 或权限条表达。
- 当前结论：适合作为 fallback 或更专业的品牌路线，但不满足“要有脸”的偏好。

### 方案 B：稠密抽象助手头像

使用 `█` / `▄` / `▀` / `▌` / `▐` 这类块字符做更厚重的头像轮廓，保留眼睛和微表情。

```text
       ▄████████▄
     ▄██  ●  ●  ██▄
     ██    ▾     ██
     ██  ▄████▄  ██
      ▀██▄    ▄██▀
        ▀██████▀
```

- 优点：有脸，有品牌感，轮廓比线框机器人更厚、更稳定。
- 缺点：不同终端字体下块字符可能有高度/基线差异，需要真机截图验证。
- 当前结论：比现有线框机器人更可行，但还需要继续找更高级的形象方向。

### 方案 C：像素矩阵渲染 mascot

技术方案从手写 ASCII 改成数据驱动：定义 `16x12` 或 `20x14` 对称 bitmap，再渲染成半块字符、象限块或 Braille 字符。

```text
      ▗▄▄▄▄▄▄▖
    ▗█  ●  ● █▖
    █▌   ▾   ▐█
    █▌ ▗▄▄▄▖ ▐█
     ▀▙▖   ▗▟▀
       ▀▀▀▀▀
```

- 优点：对称性由数据保证，状态帧可复用同一骨架，后续可做轻动画。
- 缺点：实现成本高于手写字符串，且 Braille/半块字符兼容性要验证。
- 当前结论：如果继续坚持“有脸 + 精致 + 可控”，这是更工程化的路线。

### 方案 D：品牌章 + 状态 glyph

放弃完整卡通形象，改为精致 `GC` monogram 加状态符号。

```text
     ╭────────╮
     │   GC   │   ◉ ready
     ╰────────╯
```

- 优点：极简、稳定、专业，不容易出现不对称和低像素问题。
- 缺点：放弃 mascot 的人格化，品牌记忆点较弱。
- 当前结论：适合工程工具专业感路线，但不是当前优先方向。

### 方案 E：FIGlet 小型品牌字标

基于 FIGlet / Go FIGlet 生成 `Go Claude` 或 `GC`，再人工筛选字体并压缩到 5-6 行，主视觉从“卡通形象”切换成更成熟的 CLI 品牌字标。

```text
   ____  ____
  / ___|/ ___|
 | |  _| |
 | |_| | |___
  \____|\____|
```

- 优点：成熟 CLI 工具感强，识别稳定，不依赖复杂脸部细节。
- 缺点：没有完整 mascot 的人格化，表情状态需要通过颜色、状态徽章或权限条补充。
- 当前结论：适合作为高质感保底路线；如果后续 mascot 继续不稳定，可以退回该方向。

### 方案 F：字标 + 小脸状态徽章

左侧主视觉使用 `Go Claude` / `GC` 字标，旁边或右下角放一个极小的 face badge。品牌感由字标承担，脸只承担状态表达。

```text
   Go Claude
      GC   ◉‿◉
```

危险态可变为：

```text
   Go Claude
      GC   ◆━◆
```

- 优点：兼顾品牌识别和“有脸”的诉求，不再让复杂 mascot 承担全部视觉压力。
- 缺点：脸部存在感较弱，如果 badge 太小，用户可能感知不到 mascot。
- 当前结论：当前更推荐的折中方向；比完整机器人更不容易丑，也比纯字标更有情绪。

### 方案 G：Block Elements 厚像素头像

放弃细线 box drawing，改用 Unicode block elements 形成厚像素头像，例如 `█` / `▄` / `▀` / `▌` / `▐` / `▖` / `▗` / `▘` / `▝`。整体更像像素插画，而不是线框图标。

```text
      ▄▄▄▄▄▄▄▄
    ▄█  ●  ●  █▄
    █▌   ▾    ▐█
    █▌ ▄▄▄▄   ▐█
     ▀▄      ▄▀
       ▀▀▀▀▀▀
```

- 优点：轮廓更厚、更稳定，远看更像完整形象，适合做默认/思考/危险三态。
- 缺点：块字符在不同终端字体下可能出现垂直贴合问题，必须做真机截图和金标验证。
- 当前结论：如果要继续做真正 mascot，这是比线框机器人更值得验证的方向。

### 方案 H：Braille 高分辨率点阵头像

使用 Braille Patterns 做更高分辨率的点阵图，用更少列数表达曲线、脸部和外轮廓。

```text
   ⡠⠔⠒⠒⠢⡀
  ⡜  ●  ●  ⢣
  ⡇   ▾    ⢸
  ⠘⢄____⡠⠃
```

- 优点：同样宽度下细节密度更高，可以做出更柔和的轮廓和表情。
- 缺点：兼容性风险最高；部分终端字体会显得碎、糊、基线不齐。
- 当前结论：只适合作为实验方向，不建议直接作为默认实现。

### 方案 I：Dense Abstract Mark

不做人、不做机器人，改成类似“智能核心 / 结晶 / 节点网络”的抽象标识。用对称稠密符号表达智能感和产品识别。

```text
        ╭──◆──╮
     ◆──┤ GC ├──◆
        ╰──◆──╯
          ╱ ╲
        ◆     ◆
```

- 优点：更高级、更品牌化，避开卡通 mascot 容易幼稚的问题。
- 缺点：亲和力弱，不满足强“脸部表情”的诉求。
- 当前结论：适合作为品牌标识方向；如果最终放弃卡通脸，可以优先考虑。

## 紧凑宽屏备选

如果后续还要进一步压缩，可以退到单行信息版。该版本仍然保留完整脸部，不压缩表情。


## 窄屏降级稿

小终端不要强行画大卡片，改成紧凑 key-value。

