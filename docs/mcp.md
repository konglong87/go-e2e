# MCP 扩展

MCP（Model Context Protocol）用于把外部工具和服务接入 Agent。go-e2e 将 MCP 能力放在工具、权限和运行时边界内，
不是让外部服务绕过现有审批和安全规则。

## 什么时候使用 MCP？

适合把以下能力接入 Agent：

- 查询内部知识库或项目服务；
- 读取设计、工单、监控等外部系统；
- 调用一个已有的开发工具，而不是重新实现一套 Tool；
- 将团队共享的操作能力封装成统一接口。

如果只是保存一组提示词和任务流程，优先考虑 [Skills](usage/README.md)；如果是模型接入协议，使用 Provider；
如果是核心运行时必须拥有的能力，再考虑直接实现 Tool。

## 接入前的检查清单

- 明确 MCP server 的进程、网络和凭据边界；
- 只暴露完成任务所需的最小工具集合；
- 对写操作、删除操作和外部副作用设置审批；
- 为超时、错误、重复调用和部分成功设计回滚或重试策略；
- 用合成数据完成首次验证；
- 在日志和 Issue 中脱敏 API Key、Cookie、内部 URL 与用户数据。

## 推荐实施路径

1. 先在本地启动 MCP server，并用一个只读工具验证连接；
2. 为工具写清楚输入、输出、错误和权限说明；
3. 在 go-e2e 中接入最小工具集；
4. 用一个可复现的任务验证模型选择工具、工具返回结果和最终交付；
5. 再逐步增加写操作和长期任务能力。

## 贡献一个 MCP 示例

欢迎提交文档或示例 PR。一个好的示例至少应包含：

- MCP server 的来源和许可证；
- 安装与启动命令；
- go-e2e 侧的配置方式；
- 一个只读任务和一个写操作任务；
- 权限边界、失败行为和清理步骤。

提交前请阅读 [贡献指南](../CONTRIBUTING.md)。
