# go-e2e Product V2 Implementation

## Approved Contract

- Product, primary executable and source entry: go-e2e, cmd/go-e2e.
- Canonical environment prefix: GO_E2E_; previous product variables are compatibility inputs.
- Global configuration stays ~/.golang-cc/settings.json. Do not read external model credentials.
- Keep protocol adapters and SDK attribution. External CLAUDE.md/memory compatibility is context-only.
- --session-id opens or creates a persistent conversation and appends with previous context.
- WebUI 2.0 and desktop-v2 are the maintained surfaces.
- Settings entry stays above the sidebar identity; settings use compact secondary navigation.
- Model, observability, profile, appearance, pet, Feishu and multi-agent pages use actual services.
- Appearance and pet preferences use the global settings document with reversible previews.
- SQLite is the local default; MySQL is an explicit deployment choice.
- README assets must be generated renders or actual application captures, never fabricated UI.

## Architecture

Reuse the versioned settings document API and shared draft; typed appearance settings add
validation without creating a second configuration store. Runtime protocol adapters remain
unchanged. Session selection is resolved before context reconstruction and transcript opening.
The desktop host owns native window operations; browser rendering stays host-independent.
Blender exports reusable GLB assets; Three.js renders them on demand and disposes resources.
Do not introduce databases for visual preferences or duplicate telemetry ingestion.
